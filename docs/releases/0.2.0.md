# Token Lens 0.2.0

这一版让价格跟得上新模型，日志多、刷新勤的时候同步也快得多；原来的迷你窗口改叫小窗，还能再缩成更小的迷你模式。

## 小窗和迷你模式

- 原来的「迷你窗口」改名叫「小窗」，用法不变。
- **迷你模式**：嫌小窗挡住别的窗口时，点小窗标题栏的「缩成迷你模式」，它会缩成一个小条，只显示今天的 token 和金额。单击小条（或按 Enter、空格）就展开回小窗。
- 按住小条可以拖到任意位置。Windows 上把它拖到屏幕左边或右边，甚至拖出边缘，它会藏进边缘，只露出一个图标；鼠标移上去会滑出来，移开后再缩回去。那一侧如果还连着另一块显示器，就只贴着边缘，不会藏到另一块屏幕上。
- 关掉程序时在迷你模式，下次打开还是迷你模式，位置也保留。
- macOS 上只能在屏幕内拖动，不会藏进边缘。

## 价格：新模型不用等发新版

- **价格表每天联网更新**：程序每天最多一次，从本项目仓库下载核对过的价格表，比程序自带的新才会用，用上后账本里的金额按新价重算。只下载，不上传；在「价格与设置」的「联网与更新」里可以关掉「自动更新价格表」，关掉后只用程序自带的价格表。
- **查不到价格的模型可以自己填**：在价格表里展开这个模型，或者在明细里点「未定价」旁边的「填写价格」。美元、人民币都能填，人民币按填写时的汇率折成美元保存，以后汇率变了也不重算；也可以用「照已有模型的价格填」。手填的价只存在这台电脑上，标为「手填」，随时能改或删。「照已有模型的价格填」是一个可以搜索的菜单，打上模型名就能找到。
- 以后价格表有了这个模型的官方价，仍按你填的算，并提示你可以改用价格表的价。
- 只有价格表里查不到的模型能手填；已经有公开价的模型不能改。

## 同步更快

- 同一个工具里只有少数日志文件变了时，没变的文件不再重写账本。
- 程序开着时，从第二次同步起，没变的日志连缓存也不再读一遍。
- 在合成测试里，2,561 个日志文件中有 2 个变化时，一次同步从约 8 秒降到约 0.7 秒；文件越多，省得越多。程序刚打开后的第一次同步还要读一遍缓存，约 4 秒。
- 查找日志文件时，每个文件夹只列一次（以前 Codex 的日志文件夹要列四次）。
- 定时同步改为上一次同步结束后再等一个刷新间隔。小窗刷新间隔设得很短、同步又比较慢时，不会再一次接一次地连着跑、一直占着 CPU。

## 其他改进

- 从侧栏或总览进入「用量明细」时，「拆开看」默认按项目。从某个工具、模型或项目点进去时，还和以前一样。

## 修复

- Windows 上创建桌面快捷方式后，桌面会马上显示它，不用再手动刷新。
- 首次统计进行中，来源页偶尔读取失败。
- 同步刚结束就导出诊断日志时，最后这次同步的记录有时会漏掉。

## 命令行和导出的变化

`token-lens-cli` 和明细导出里，一组记录全部没有价格时，`cost_usd` 和 `cost_micros` 现在是 `null`，以前是 `"0.000000"` 和 `0`。没有记录的空范围仍然是 0，本地模型仍按 0 计价。用脚本读这两个字段的话，请把 `null` 当作“未知”处理。

## 升级须知

- 直接用新版替换旧的程序文件夹即可，账本和设置都保留。
- 升级后第一次同步会把已有日志的缓存整理一遍，比平时慢（日志多的话可能要一两分钟），之后恢复正常。

## 已知限制

- 程序没有代码签名，macOS 版也没有公证，第一次打开时系统会拦一下，放行方法见安装指南。
- macOS 版在 GitHub 的 macOS 机器上构建并跑过冒烟测试，还没有在真机上完整验收。
- 没有安装程序，两个平台都是解压即用的 zip。
- 标为“实验性”的工具只用合成样本验证过，可能读不到或读不全；日志放在非默认位置的工具暂时读不到。

# Token Lens 0.2.0 (English)

This release keeps prices up to date with new models and makes syncing much faster when you have many logs or refresh often. The mini window is now called the compact window, and it can shrink further into mini mode.

## Compact window and mini mode

- The "Mini window" is renamed "Compact window" and works as before.
- **Mini mode**: when the compact window covers something you need, click "Shrink to mini mode" in its title bar. It becomes a small bar that shows only today's tokens and cost. Click the bar (or press Enter or Space) to open the compact window again.
- Drag the bar anywhere. On Windows, drag it to the left or right edge of the screen, or past it, and it tucks into the edge with only an icon showing; hover over it to slide it out, and it slides back when the pointer leaves. If another display continues on that side, the bar stays against the edge instead of hiding on the other display.
- If the app is in mini mode when you close it, it opens in mini mode at the same place next time.
- On macOS the bar can be dragged within the screen but does not tuck into the edge.

## Pricing: new models no longer wait for a new release

- **The price list updates online every day.** At most once a day, the app downloads the reviewed price table from this project's repository and uses it only if it is newer than the one built in; costs in the ledger are then recalculated. It only downloads and never uploads. Turn off "Update price list automatically" under Network and updates in Pricing & settings to use only the built-in table.
- **Add a price for a model that has none.** Expand the model in the price table, or click "Add price" next to "Unpriced" in Breakdown. Enter USD or CNY; CNY is converted at the rate on the day you save it and is not recalculated later. You can also use "Copy prices from" an existing model. Your prices stay on this computer, are marked "Manual", and can be changed or removed at any time. "Copy prices from" is a searchable menu: type part of a model name to find it.
- If the price table later gets an official price for that model, your price is still used and the app offers to switch to the table's price.
- Only models missing from the price table can be priced by hand; models with a list price cannot be changed.

## Faster sync

- When only a few log files of a tool have changed, unchanged files no longer rewrite the ledger.
- While the app is open, from the second sync on, unchanged logs are no longer read again even from the cache.
- In a synthetic test with 2,561 log files of which 2 changed, one sync went from about 8 seconds to about 0.7 seconds; the more files, the bigger the saving. The first sync after the app starts still reads the cache once and takes about 4 seconds.
- Each log folder is listed once while looking for log files (Codex folders used to be listed four times).
- Timed syncs now wait one refresh interval after the previous sync finishes. With a short compact window interval and a slow sync, syncs no longer run back to back and keep the CPU busy.

## Other improvements

- Opening Breakdown from the sidebar or the overview now splits by project by default. Opening it from a specific tool, model or project works as before.

## Fixes

- On Windows, a newly created desktop shortcut now appears right away without refreshing the desktop.
- The Sources page could occasionally fail to load during the first count.
- Exporting diagnostics right after a sync could leave out that last sync.

## CLI and export changes

In `token-lens-cli` and the breakdown export, a group whose records are all unpriced now has `cost_usd` and `cost_micros` set to `null` instead of `"0.000000"` and `0`. Empty ranges are still 0, and local models are still priced at 0. If a script reads these fields, treat `null` as unknown.

## Upgrading

- Replace the old app folder with the new one; your ledger and settings are kept.
- The first sync after upgrading reorganizes the cache of existing logs and is slower than usual (a minute or two with many logs); after that it is back to normal.

## Known limitations

- The app is not code-signed and the macOS build is not notarized, so the system stops it on first launch; the installation guide shows how to allow it.
- The macOS build is built and smoke-tested on GitHub's macOS runners but has not been fully tested on real hardware.
- There is no installer; both platforms ship as zip files.
- Tools marked experimental are verified only against synthetic samples and may be missed or read incompletely; logs stored in non-default locations are not read yet.
